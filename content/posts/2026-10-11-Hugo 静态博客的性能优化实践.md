## 引言

Hugo 以“世界上最快的静态站点生成器”著称，但**生成快 ≠ 访问快**。很多 Hugo 博客在本地 `hugo server` 时秒开，部署到线上后却因为未压缩的图片、阻塞渲染的 JS、缺失的缓存策略而变得迟缓。本文记录我对一个中型 Hugo 博客（约 120 篇文章、300+ 图片）进行性能优化的完整过程，最终将 Lighthouse 性能分从 62 提升到 98，首屏加载时间从 3.1s 降至 0.8s。

---

## 一、图片处理：从 4MB 到 400KB

图片通常是静态博客最大的性能瓶颈。我原先直接引用原始 PNG 截图，单张动辄 1.5MB。Hugo 内置的 **Image Processing** 配合 Page Resources 可以自动完成缩放、格式转换与压缩。

### 1.1 使用 Page Bundle 管理图片

将文章改为 Page Bundle 结构：

```
content/posts/my-post/
├── index.md
└── cover.png
```

### 1.2 在模板中生成 WebP 与响应式 srcset

```html
{{ $img := .Resources.GetMatch "cover.png" }}
{{ $webp := $img.Resize "800x webp q80" }}
{{ $small := $img.Resize "400x webp q75" }}
{{ $large := $img.Resize "1200x webp q80" }}

<img
  src="{{ $webp.RelPermalink }}"
  srcset="{{ $small.RelPermalink }} 400w,
          {{ $webp.RelPermalink }} 800w,
          {{ $large.RelPermalink }} 1200w"
  sizes="(max-width: 600px) 400px, 800px"
  loading="lazy"
  decoding="async"
  width="{{ $webp.Width }}"
  height="{{ $webp.Height }}"
  alt="{{ .Title }}">
```

要点：
- **WebP 格式**平均比 PNG 小 60%–80%；
- 显式设置 `width`/`height` 避免布局偏移（CLS）；
- 首屏图片用 `loading="eager"`，其余 `lazy`。

优化后，首页图片总体积从 4.2MB 降到 380KB。

## 二、代码分割与资源精简

### 2.1 拆分关键 CSS

Hugo Pipes 可以对 SCSS 进行编译、压缩与指纹化：

```go-html-template
{{ $style := resources.Get "scss/main.scss"
    | resources.ExecuteAsTemplate "main.scss" .
    | toCSS (dict "outputStyle" "compressed")
    | fingerprint }}
<link rel="stylesheet" href="{{ $style.RelPermalink }}"
      integrity="{{ $style.Data.Integrity }}">
```

对于首屏关键样式，我抽取 `critical.scss` 内联到 `<head>`，其余样式异步加载：

```html
<link rel="preload" href="{{ $style.RelPermalink }}" as="style"
      onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="{{ $style.RelPermalink }}"></noscript>
```

### 2.2 JS 按需加载

原主题把所有脚本打包成一个 `bundle.js`（约 180KB）。我改为：

- 使用 `defer` 加载非关键脚本；
- 评论、代码高亮等组件用 `IntersectionObserver` 懒加载；
- 用 `resources.Concat` 合并真正必要的模块。

```go-html-template
{{ $main := resources.Get "js/main.js" }}
{{ $lazyload := resources.Get "js/lazyload.js" }}
{{ $js := slice $main $lazyload
    | resources.Concat "js/bundle.js"
    | minify | fingerprint }}
<script src="{{ $js.RelPermalink }}" defer></script>
```

JS 体积从 180KB 降到 42KB，且不再阻塞首屏渲染。

## 三、CDN 与缓存策略

### 3.1 静态资源指纹化 + 长缓存

Hugo 的 `fingerprint` 会为文件名追加内容哈希，因此可以放心设置一年缓存：

```
/assets/*  Cache-Control: public, max-age=31536000, immutable
/*.html    Cache-Control: public, max-age=0, must-revalidate
```

在 Netlify 中通过 `_headers` 文件配置：

```
/assets/*
  Cache-Control: public, max-age=31536000, immutable

/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
```

### 3.2 启用 Brotli 与 HTTP/3

Cloudflare 与 Netlify 均默认支持 Brotli。HTML 与 CSS 经 Brotli 压缩后体积再降约 20%。同时在 DNS 层开启 HTTP/3，减少握手延迟。

### 3.3 预连接关键域名

```html
<link rel="preconnect" href="https://cdn.example.com" crossorigin>
<link rel="dns-prefetch" href="https://analytics.example.com">
```

## 四、其他细节优化

1. **字体子集化**：仅保留常用字符集，woff2 从 220KB 降到 28KB；
2. **禁用未使用的功能**：关闭 `enableGitInfo` 与不需要的 taxonomies，构建时间减少 40%；
3. **开启 Hugo 的 `minify` 与 `--gc`**：

```bash
hugo --minify --gc --enableGitInfo=false
```

4. **使用 `hugo server --disableFastRender` 做真实性能验证**，避免开发模式掩盖问题。

## 总结

Hugo 的性能优化并不复杂，核心思路是：**让浏览器少下载、晚下载、缓存好**。图片走 WebP + 响应式、CSS/JS 做分割与懒加载、静态资源指纹化并配合 CDN 长缓存，这三板斧下来，绝大多数 Hugo 博客都能进入 1 秒俱乐部。建议每次改动后用 Lighthouse 与 WebPageTest 复测，避免“优化”变成新的负担。

如果你也在维护 Hugo 博客，不妨从图片处理开始，收益最直观。欢迎在评论区分享你的优化技巧。
